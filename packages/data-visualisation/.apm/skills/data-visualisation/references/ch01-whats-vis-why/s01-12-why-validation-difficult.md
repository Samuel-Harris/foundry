# 1.12 Why Is Validation Difficult?

## Principle

<!-- verbatim p.39 -->
> The problem of validation for a vis design is difficult because there are so many questions that you could ask when considering whether a vis tool has met your design goals.
<!-- /verbatim -->

## The open questions

The section poses questions rather than answers [p.39]:

- **What does better mean?** Faster, more fun, more effective, and how to measure insight or engagement [p.39].
- **Better than what?** Another vis system, doing the same things manually without visual support, or doing them completely automatically [p.39].
- **Better at what?** How to choose the task users do when testing the system [p.39].
- **Better for whom?** An expert of decades or a novice who needs the task explained; a long-time user of the system or a first-time one [p.39].
- **Faster in what sense?** Users may be limited by their own thought, their ability to move the mouse, or the computer's speed in drawing each picture [p.39].
- **Which data?** What benchmark data to test with, and which classes of data the system suits [p.39].
- **Image quality.** How to measure the quality of an image a vis tool generates, and how well automatically computed quality metrics match human judgements [p.39].
- **Computation.** Whether algorithm complexity depends on the number of data items or the number of pixels, and whether there is a trade-off between speed and memory [p.39].
