# 3.3 Who: Designer or User

## Who holds the goal or makes the choice

<!-- verbatim p.69 -->
> It’s sometimes useful to augment an analysis instance specification by indicating who has a goal or makes a design choice: the designer of the vis or the end user of the vis. Both cases are common.
<!-- /verbatim -->

## The specific-to-general continuum

Vis tools fall along a continuum from specific to general [p.70].

- **Specific tools** are narrow: the designer builds many choices into the tool that the user cannot override. They are limited in the data and tasks they address, but users do not face an overwhelming array of design choices [p.70].
- **General tools** are flexible and leave users many choices. That breadth is both a strength and a limitation: users have a lot of power but may make ineffective choices if they lack a deep understanding of vis design issues [p.70].

## Data handled at each end

Specialised tools target specific contexts with a narrow range of data configurations, especially those created through a problem-driven process. Their datasets are often complex combinations and special cases of the basic data types, and mix original and derived data [p.70].

General tools handle a wide range of data flexibly, for example by accepting any dataset of one type as input: tables, fields or networks. Some particularly broad tools handle several dataset types, for instance supporting transformations between tables and networks [p.70].
