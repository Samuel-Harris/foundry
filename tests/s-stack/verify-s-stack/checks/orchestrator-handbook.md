# Phase `orchestrator-handbook` checks

Phase `orchestrator-handbook` ships `handbooks/orchestrator.md`, the orchestrator's handbook. It is prose, so the behavioural checks are cold reads. A cold read starts a fresh subagent, gives it only the files and the scenario the check names, tells it to read nothing else, and asks the questions. Its answer passes when it agrees in substance with every point of the expected answer. Wording may differ, but a missing or contradicting point fails the check. Wait for every cold-read subagent to finish before reporting.

Every scenario uses placeholder data: the feature `acme-widgets`, the default branch `trunk`, made-up SHAs and `example.invalid` addresses. The files, relative to the repository root:

- The handbook, `packages/s-stack/.apm/skills/sam-mode/handbooks/orchestrator.md`
- The reference, `packages/s-stack/.apm/skills/sam-mode/references/status-and-messages.md`
- The phase session handbook, `packages/s-stack/.apm/skills/sam-mode/handbooks/phase-session.md`, the other side of the handshakes in cold reads L, M, AB, AC, AG, AH, AJ, AN, AO, AP, AQ, AR, AU, AV, AW and AX
- The planner handbook, `packages/s-stack/.apm/skills/sam-mode/handbooks/planner.md`, the other side of the planner restart in cold reads AH and AP

The handbook records, for each pull request, the last head named in the `pushed` line of its phase's last `prs-open`, the head the PR creator pushed. Once the phase has settled, in PR with nothing the orchestrator sent it unanswered, it compares each open pull request's head with that recorded head, and for each that differs it sends the phase an `instruction` to refresh that pull request, naming it and both heads. It does not judge which commits are new; the PR creator does. A head that moves while a round is unanswered, by the phase's own PR creator or anyone else, is therefore not compared until the phase settles, and the `prs-open` that answers the round records the head its `pushed` line names, so a commit made after that push is still compared. A developer's commit, GitHub's "Update branch" and a forge rebase all draw such an instruction, the last two as a round that changes nothing. In a read where a pull request's head differs from its head at the last `prs-open` while its phase is settled, and the expected answer does not mention it, an answer that sends that refresh `instruction` passes. An answer that sends a `fix-round` of the kind "Feedback on a pull request" for a moved head fails.

### Abort recovery in a scratch repository

The handbook says that when `git merge --abort` refuses because a hook rewrote a file, `git checkout -- <path>` and a second abort recover, and that each file outside `.foundry/` that `git status --porcelain --untracked-files=no` still lists is then restored, because a hook can rewrite files the merge did not touch. This script builds a throwaway repository under `mktemp -d`, with placeholder names and a hermetic git configuration. Its pre-commit hook refuses a merge commit after rewriting the staged lockfile and `src/widgets/settings.py`, which the merge does not touch. The script checks that the first abort refuses, naming the lockfile, that the second abort leaves only `settings.py` rewritten, that a later merge which changes `settings.py` refuses before the clean-up, and that after the handbook's clean-up the tree is clean, `HEAD` has not moved and that merge starts. It touches nothing outside its temporary directory.

```bash
bash <<'SCRIPT'
set -u
export GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT
fail() { echo "FAIL: $*"; exit 1; }
cd "$tmp" && git init -q -b trunk repo && cd repo
git config user.name placeholder && git config user.email placeholder@example.invalid
mkdir -p packages/widgets src/widgets hooks
echo '{"v": 1}' > packages/widgets/lock.json
echo 'core = 1' > src/widgets/core.py
echo 'settings = 1' > src/widgets/settings.py
git add packages src && git commit -q -m base
git checkout -q -b acme-widgets-phase-beta
echo 'core = 2' > src/widgets/core.py
git commit -q -am "beta change"
tip="$(git rev-parse HEAD)"
echo 'settings = 2' > src/widgets/settings.py
git commit -q -am "beta later change to settings"
later="$(git rev-parse HEAD)"
git checkout -q -b acme-widgets trunk
before="$(git rev-parse HEAD)"
printf '#!/bin/sh\necho "{\\"v\\": 3}" > packages/widgets/lock.json\necho "settings = 9" > src/widgets/settings.py\necho "lockfile stale, rewritten" >&2\nexit 1\n' > hooks/pre-commit
chmod +x hooks/pre-commit
git merge -q --no-ff --no-commit "$tip" || fail "the merge should stop cleanly before committing"
git diff --cached --name-only | grep -q settings.py && fail "the merge should not touch settings.py"
echo '{"v": 2}' > packages/widgets/lock.json && git add packages/widgets/lock.json
git -c core.hooksPath=hooks commit -q --no-edit 2>/dev/null && fail "the hook should refuse the commit"
git merge --abort 2>abort.err && fail "the first abort should refuse after the hook rewrote a staged file"
grep -q "lock.json" abort.err || fail "the refused abort should name lock.json: $(cat abort.err)"
git rev-parse -q --verify MERGE_HEAD >/dev/null || fail "MERGE_HEAD should remain after the refused abort"
rm -f abort.err
git checkout -- packages/widgets/lock.json
git merge --abort || fail "the abort should succeed after git checkout of the named file"
git rev-parse -q --verify MERGE_HEAD >/dev/null && fail "MERGE_HEAD should be gone"
[ "$(git rev-parse HEAD)" = "$before" ] || fail "HEAD moved"
left="$(git status --porcelain --untracked-files=no | cut -c4-)"
[ "$left" = "src/widgets/settings.py" ] || fail "after the abort only the untouched settings.py should stay rewritten, got: $left"
git merge -q --no-ff --no-commit "$later" 2>/dev/null && fail "a merge touching the rewritten settings.py should refuse before the cleanup"
git rev-parse -q --verify MERGE_HEAD >/dev/null && fail "the refused merge should leave no MERGE_HEAD"
git status --porcelain --untracked-files=no | cut -c4- | grep -v '^\.foundry/' | while read -r path; do git checkout -- "$path"; done
[ -z "$(git status --porcelain --untracked-files=no)" ] || fail "tracked files changed after the cleanup: $(git status --porcelain)"
[ "$(git rev-parse HEAD)" = "$before" ] || fail "HEAD moved"
git merge -q --no-ff --no-commit "$later" || fail "the next merge should start after the cleanup"
git merge --abort
echo "blocked abort recovered: refused, then checkout, abort and cleanup of the untouched file left HEAD at $before with a clean tree"
SCRIPT
```

Expected: exit `0` and a last line starting `blocked abort recovered:`. Git prints `Automatic merge went well; stopped before committing as requested` twice on the way. Without the `git status` clean-up, the script fails at its `tracked files changed after the cleanup` assertion, and without the `git checkout` of the named lockfile, at the second abort.

A developer's suggestion on 31 moves its head, so one refresh instruction is sent naming both heads, and no second one while it is unanswered. An "Update branch" merge of `trunk` into 31 moves its head, so one round is sent. After 31 is squash-merged into `trunk`, the forge's rebase of 32 onto `trunk` moves its head, so one round is sent. After each answering `prs-open` the heads are recorded anew, so no further round is sent, including after the PR creator's own refresh of 32 before its `prs-open`. The script then runs the same history under two mutants of the rule and requires each to fail at its own assertion: one that treats a head containing the recorded head as unchanged, so it skips a suggestion, and one that sends a round for an unchanged head. It touches nothing outside its temporary directory.

```bash
bash <<'SCRIPT'
set -u
export GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT
moved() {
  case "$rule" in
    handbook) [ "$1" != "$2" ] ;;
    skips-moved-head) [ "$1" != "$2" ] && ! git merge-base --is-ancestor "$1" "$2" ;;
    sends-for-unchanged-head) true ;;
  esac
}
prs_open() {
  for pr in "$@"; do git rev-parse "acme-widgets-pr$pr" > "$state/recorded-$pr"; done
  rm -f "$state/unanswered"
}
tick() {
  [ -e "$state/unanswered" ] && return 0
  for pr in $(cat "$state/open"); do
    recorded="$(cat "$state/recorded-$pr")" head="$(git rev-parse "acme-widgets-pr$pr")"
    if moved "$recorded" "$head"; then
      echo "instruction: refresh pull request $pr, recorded head $recorded, current head $head"
      touch "$state/unanswered"
    fi
  done
}
expect() {
  want="$1" what="$2" out="$(tick)"
  n="$(printf '%s' "$out" | grep -c '^instruction:')"
  [ "$n" = "$want" ] || { echo "FAIL ($rule): $what: expected $want round(s), got $n: $out"; return 1; }
  [ "$want" = 0 ] || printf '%s' "$out" | grep -q "recorded head $3, current head $4" || { echo "FAIL ($rule): $what: the round should name both heads: $out"; return 1; }
}
scenario() {
  rule="$1" repo="$tmp/$1" state="$tmp/$1-state"
  mkdir -p "$state" && git init -q -b trunk "$repo" && cd "$repo" || return 1
  git config user.name placeholder && git config user.email placeholder@example.invalid
  mkdir -p packages/widgets src/widgets docs
  echo '{"v": "base"}' > packages/widgets/lock.json
  echo 'core = 1' > src/widgets/core.py && echo 'render = 1' > src/widgets/render.py && echo 'style' > docs/style.md
  git add . && git commit -q -m base
  git checkout -q -b acme-widgets-pr31
  echo 'core = 2' > src/widgets/core.py && git commit -q -am "phase change to core"
  echo '{"v": "pr31"}' > packages/widgets/lock.json && git commit -q -am "chore: regenerate generated files"
  git checkout -q -b acme-widgets-pr32
  echo 'tav = 1' > src/widgets/tav.py && git add src/widgets/tav.py && git commit -q -m "stacked change"
  echo '31 32' > "$state/open"
  prs_open 31 32
  expect 0 "heads unchanged since prs-open" || return 1
  git checkout -q acme-widgets-pr31
  before="$(git rev-parse HEAD)"
  echo 'render = 2' > src/widgets/render.py && git commit -q -am "Apply suggestions from code review"
  expect 1 "a developer's suggestion moved the head" "$before" "$(git rev-parse HEAD)" || return 1
  expect 0 "the refresh instruction is still unanswered" || return 1
  prs_open 31 32
  expect 0 "the answering prs-open recorded the suggestion's head" || return 1
  git checkout -q trunk
  echo 'style 2' > docs/style.md && git commit -q -am "colleague's docs change"
  git checkout -q acme-widgets-pr31
  before="$(git rev-parse HEAD)"
  git merge -q --no-ff trunk -m "Merge branch 'trunk' into acme-widgets-pr31" || return 1
  expect 1 "an \"Update branch\" merge moved the head" "$before" "$(git rev-parse HEAD)" || return 1
  prs_open 31 32
  expect 0 "the answering prs-open recorded the merge's head" || return 1
  git checkout -q acme-widgets-pr32
  git merge -q --no-ff acme-widgets-pr31 -m "refresh onto pull request 31" || return 1
  prs_open 31 32
  expect 0 "the PR creator's own refresh before its prs-open" || return 1
  git checkout -q trunk
  git merge -q --squash acme-widgets-pr31 >/dev/null && git commit -q -m "Parent pull request (#31)"
  echo '32' > "$state/open"
  before="$(git rev-parse acme-widgets-pr32)"
  git rebase -q --onto trunk acme-widgets-pr31 acme-widgets-pr32 >/dev/null 2>&1 || return 1
  git merge-base --is-ancestor "$before" HEAD && { echo "FAIL ($rule): the forge rebase should rewrite the child's head"; return 1; }
  expect 1 "the forge rebased the stack child after its parent merged" "$before" "$(git rev-parse HEAD)" || return 1
  prs_open 32
  expect 0 "the answering prs-open recorded the rebased head" || return 1
}
( scenario handbook ) || exit 1
for case in "skips-moved-head:a developer's suggestion moved the head" "sends-for-unchanged-head:heads unchanged since prs-open"; do
  mutant="${case%%:*}" at="${case#*:}"
  out="$( (scenario "$mutant") )" && { echo "FAIL: the $mutant mutant passed"; exit 1; }
  printf '%s' "$out" | grep -q "^FAIL ($mutant): $at:" || { echo "FAIL: the $mutant mutant failed elsewhere: $out"; exit 1; }
  echo "mutant $mutant fails at: $at"
done
echo "one refresh instruction per moved head, naming both heads, none for an unchanged head or while one is unanswered, and none after the answering prs-open"
SCRIPT
```

Expected: exit `0`, the lines `mutant skips-moved-head fails at: a developer's suggestion moved the head` and `mutant sends-for-unchanged-head fails at: heads unchanged since prs-open`, and the last line `one refresh instruction per moved head, naming both heads, none for an unchanged head or while one is unanswered, and none after the answering prs-open`.
